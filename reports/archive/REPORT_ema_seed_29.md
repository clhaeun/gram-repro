### sh 수정 diff (`train_nqueens8_fix.sh`)
50번이 SEED 지원을 아직 push 하지 않아(`git pull` = up to date) 직접 추가했다.

```diff
+# seed 를 환경변수로. 기본 0 = config/cfg_pretrain.yaml 기본값과 동일 -> 기존 호출 동작 불변.
+SEED="${SEED:-0}"
...
-  epochs=${EPOCHS} eval_interval=200 \
+  epochs=${EPOCHS} eval_interval=200 seed=${SEED} \
```

기본값 0 은 `config/cfg_pretrain.yaml` 과 같아 **기존 호출의 동작은 바뀌지 않는다**.

**수정 방식(중요)**: 수정 시점에 GPU 0/1 의 `b160`/`b170` 이 **이 sh 를 실행 중**이었다.
bash 는 스크립트를 실행하면서 필요한 만큼씩 읽으므로, 실행 중 파일을 in-place 로 고치면
마지막 명령(torchrun)이 끝난 뒤 바뀐 바이트 오프셋에서 이어 읽어 깨질 수 있다.
그래서 임시 파일에 수정본을 만들고 `mv` 로 **inode 를 교체**했다(128713277 → 202388597).
실행 중이던 bash 는 기존 inode 를 계속 참조하므로 영향이 없고, 두 run 모두 이후 정상 완주했다.

이번 peak 선택은 지시대로 곡선(=EMA) 기준이므로, **.live 쪽 정점은 놓쳤을 가능성이 있다**
(측정하지 않았으므로 어느 step 이 .live peak 인지는 모른다).

대부분 100% 이나 두 곳이 무너졌다: **1.8 ON s0 final(EMA) 38.60/39.38%**, 1.8 ON s1 peak(EMA) 80.70/81.74%.

**EMA on 은 seed 편차를 줄이지 못했다.** EMA on 두 seed 사이 폭(25.3배)이 EMA off 쪽 폭(8.0배)보다
오히려 크다. 다만 각 칸이 seed 1개 측정이라 **"EMA on 이 편차를 키운다"고 단정하지 않는다** —
폭을 재려면 셀당 seed 가 더 필요하다.

**ON β=1.8 의 62.68% 는 이 서버에서 재현되지 않았다.** EMA on/off, seed 0/1/3 어느 조합도
그 근처에 못 갔고(EMA 기준 0.38~9.60%, `.live` 포함해도 최대 29.71%), 기존 62.68% 는
다른 서버·다른 실행의 단일 측정이다. 재현 실패인지 seed 편차인지는 **50번의 1.8 재현 결과**와
합쳐야 갈린다.
