## 1. 측정 4축 규약 (`metric_defs` 기준, 섞어 읽지 말 것)

pull 해 온 `experiments/sweep_harness.py:106-123` 의 `METRIC_DEFS` 를 그대로 따른다.

| 축 | 지표 | 뜻 |
|---|---|---|
| **단일시도** | `prior_all_samples.valid` | 퍼즐당 N 샘플을 각각 채점한 평균 = "한 번 뽑아 맞을 확률". `pass@1` 과 수학적으로 동일 |
| **pass@k** | `pass_at.20` | N 중 k 개 뽑아 1개 이상 valid 일 확률(불편추정량) |
| **selection** | `majority_at_N_valid`, `verifier_selected_at_N_valid` | N 샘플에서 1개를 고른 뒤 채점 (최빈 / 모델 자체 점수) |
| **coverage** | `coverage_at_20` | 정답해 집합을 몇 % 발견했는가. found = valid AND consistent 인 unique 보드, total = sidecar 의 per-x 전체 해 개수 |

`posterior` 는 정답 y 를 본 경로라 prior 성능과 **다른 축**이며 같이 읽지 않는다.
가중치 종류(EMA / `.live`)는 모든 표에 명시한다 — 판정은 **`.live`** 기준(감사 규약).

## 6. OFF 2.2 3회 반복 편차 — **"seed 편차"가 아니다**

| 회차 | run_name | 지정 seed | peak step | 단일시도 valid | coverage@20 |
|---|---|---|---|---|---|
| 1 | `nq8_off_b220_ema6k_s0` | 0 | 26197 | **0.7869** | 0.9905 |
| 2 | `nq8_off_b220_ema6k_s1` | 1 | 31892 | **0.6267** | 0.9747 |
| 3 | `nq8_off_b220_ema6k_s2` | 2 | 33031 | **0.3146** | 0.9206 |

```
단일시도 : 평균 0.5761   범위 0.3146~0.7869   폭 0.4723   최대/최소 2.50배
coverage : 평균 0.9619   범위 0.9206~0.9905   폭 0.0699   최대/최소 1.08배
```

**중요 — 이것을 "seed 편차"라고 부르면 안 된다.** 29번 감사(`REPORT_audit_measure.md` 0절)가
**같은 seed 로도 학습 궤적이 갈린다**는 것을 실측했다: 동일 조건 두 run 의 raw 가중치가
step 1139 에서 L2 9.15%, step 17085 에서 55.04% 차이. eval 이전 지점에서도 갈리므로
RNG 소비 차이로 설명되지 않고, 결정성 설정(`use_deterministic_algorithms` 등)은 코드에 부재하다.
→ **seed 는 통제 변수가 아니다.** 위 3회는 seed 라벨이 다르지만 실질은 **단순 반복 3회**다.

**따라서 β 순위를 정하려면 β 당 반복 3회 이상이 필요하고, 지금 표의 모든 단일 β 값(2.1, 2.3,
ON 1.6)은 반복 1회짜리 추정이다.**

### 6-1. coverage 가 단일시도보다 훨씬 안정적이다

같은 3회 반복에서 단일시도는 2.50배 갈리는데 coverage 는 1.08배다. 다른 β 들도 마찬가지로
coverage 는 0.92~0.99 좁은 범위에 모여 있다.
→ **반복이 부족한 상황에서 설정을 비교하려면 coverage 쪽이 판별력이 낫다.** 다만 coverage 가
0.92~0.99 로 포화 상태라 상위 설정 간 변별이 어렵다는 반대 문제가 있다.

## 8. 임의로 정한 것

1. **peak 를 raw(`_raw`) 곡선에서 골랐고 EMA 곡선은 쓰지 않았다** (감사 규약 4-2).
2. **정점 checkpoint 에서만 harness 를 돌렸다**(정점 근방 스캔은 안 함). 곡선 진폭이 커서
   정점 근방 3~5점을 재면 더 안정적이겠지만, 지시 범위(peak harness)를 넘어 GPU 를 더 쓰는
   판단은 하지 않았다.
3. **pull 전 harness 16회(`peak50_*`)와 pull 후 16회(`cov50_*`)가 중복 측정이다.**
   pull 전 것은 coverage 가 없어 `cov50_*` 를 본 리포트의 근거로 썼다. 두 세트의 단일시도
   값은 서로 일치한다(재현성 부수 확인).
4. **`REPORT_audit_measure.md` 이름 충돌 처리** — pull 시 29번의 같은 이름 파일과 충돌했다.
   내 것을 **`REPORT_audit_measure_50.md`** 로 개명해 보존하고 29번 것을 받았다. 덮어쓰지 않았다.
5. **coverage 는 EMA 가중치에도 측정했다**(표 4). 판정에는 안 쓰지만 EMA/live 격차를
   coverage 축에서도 보려고 남겼다.
