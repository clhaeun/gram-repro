## 3. 결과 — **논문 축(run 간 mean ± std)으로 집계**

### 3-1. 축 정정 (중요)

이전 보고의 `±0.169` 는 **예측 5,100개(255 퍼즐 × 20 샘플) 사이의 std** 였다.
논문 Table 1 캡션의 `±2.1` 은 **"mean ± standard deviation over runs"** = **run(seed) 간 std** 다.
축이 다르므로 직접 비교가 성립하지 않았다. run 별 대표값(정점 `.live`, harness seed 0/1 평균)을
모아 재집계한다:

```
run 별 conflicts_mean:
  catnd_s0 0.0718 | catnd_s1 0.0216 | add_b0 0.0454 | add_bm4 0.1181
```

| 집계 | conflict | coverage@20 |
|---|---|---|
| **bias 0 3-run** | **0.046 ± 0.025** | **0.842 ± 0.026** |
| **4-run 전체** | **0.064 ± 0.041** | **0.836 ± 0.024** |
| **논문 (8-vertex)** | **2.7 ± 2.1** | **0.858 ± 0.005** |

**서술 정정**: 이전의 "논문의 1/23~1/120" 은 **과장이다.** 논문 std 2.1 은 논문 seed 별 값이
대략 0.6~4.8 범위였다는 뜻이므로, 우리 최저 run(0.022)과 논문 평균(2.7)을 직접 비교하면 안 된다.
정확한 서술은 다음 둘이다:

- **run 평균 기준 논문의 약 1/58 (bias 0 3-run), 1/42 (4-run 전체).**
- **우리 최악 run(0.118)조차 논문 최저 추정치(≈0.6)의 약 1/5.**

**한계 명시**: 우리 3-run 은 순수 seed 반복이 아니라 arm 이 섞여 있다(concat s0/s1 + add s0).
논문의 "over runs" 와 완전히 같은 축이 되려면 **단일 config 의 seed 반복**이 필요하다
(→ 후속: concat+nodecay/bias0/β0.5 를 seed 2/3/4 추가해 seed 5개 확보 예정).

### 3-2. ± 비대칭 — 방향이 엇갈린다 (요약 금지)

| 지표 | 논문 | std/평균 | 우리(bias 0 3-run) | std/평균 |
|---|---|---|---|---|
| conflict | 2.7 ± 2.1 | **78%** | 0.046 ± 0.025 | **54%** |
| coverage@20 | 0.858 ± 0.005 | **0.6%** | 0.842 ± 0.026 | **3.1%** |

**논문은 conflict 에서 run 간 편차가 크고(78%) coverage 에서는 거의 없다(0.6%).
우리는 반대로 coverage 쪽 편차가 논문의 5배다.** 방향이 엇갈리므로
"우리가 더 안정적" / "덜 안정적" 어느 쪽으로도 요약할 수 없다. 사실만 병기한다.

## 4. 학습 과정 관측

### 4-1. bias −4 는 단색 붕괴 후 탈출했다 (영구 붕괴 아님)

`num_colors_used` 궤적 (raw):

| step | catnd_s0 | catnd_s1 | add_b0 | **add_bm4** |
|---|---|---|---|---|
| 1,881 | 2.21 | 2.23 | 2.26 | **1.000** |
| 3,762 | **3.000** | 2.992 | 3.000 | 1.016 |
| 24,453 | 2.996 | 3.000 | 3.000 | **2.016** |
| 26,334 | 3.000 | 3.000 | 3.000 | **2.918** ← 탈출 |
| 60,192 | 2.996 | 3.000 | 3.000 | 3.000 |

bias 0 3-run 은 **step 3,762 에 3색 도달**, bias −4 는 **~24.5k step 단색(conflict = 전체 edge 수
13.12 에 고정)** 에 머물다 26,334 에 탈출했다. **탈출 비용 약 7배.** 판정 기준(30k 까지 1.0 이면
붕괴 확정)에는 미해당이나, "bias −4 는 GC 에서 ~22k step 을 낭비한다" 는 사실은 남는다.

### 4-2. β×KL/lm — 100배 격차는 유지되지 않고 붕괴 후 수렴했다

| step | catnd_s0 | catnd_s1 | add_b0 | add_bm4 |
|---|---|---|---|---|
| 250 (train) | 0.37 | 0.39 | 0.40 | **37.7** |
| 5,643 | 0.04 | 0.06 | 0.05 | **0.01** |
| 9,405 | 0.14 | 0.18 | 0.18 | **0.00** |
| 26,334 | 0.13 | 0.17 | — | 0.03 ← 탈출 |
| 60,192 | 0.24 | 0.26 | 0.21 | **0.22** |

bm4 의 β×KL 은 37.7 → **0.00~0.01** 로 붕괴(= posterior collapse, KL 이 0 으로 눌림)했다가,
탈출 후 0.22 로 회복해 bias 0 arm 들과 같은 대역에 수렴했다.

`logvar_bias` 실측: −4.0 → **−3.387**(step 1,881) → **−2.805**(3,762). wd 가 bias 를 끌어올리고
있으나 속도가 KL 붕괴보다 훨씬 느리다. **순서상 KL 붕괴가 먼저, bias 회복이 뒤따른다** —
"wd 수렴 부족" 보다 **조기 posterior collapse** 가 원인에 가깝다.

## 5. 미확정 / 보류

1. **majority@20 은 아티팩트 의심 — 재측정 대기.** GC 는 `distinct@20 ≈ 20.00` 이라 원본 토큰
   최빈은 빈도 1짜리 중 첫 등장 = **사실상 무작위 1개 선택**이다. 따라서 현재의
   "verifier(0.92~0.996) > majority(0.90~0.98), 4/4" 결론은 이 아티팩트일 수 있다.
   `gc_harness.py` 에 `majority_at_N_valid_canonical`(색 치환 동치류를 합친 뒤 최빈)을 추가했고,
   GPU 확보 시 재측정한다. verifier 는 점수 기준이라 영향 없다.
2. **add vs concat 판정 불가.** concat(0.022, 0.072) vs add(0.045) 가 concat 내부 seed 폭(0.050)
   안에 섞인다. 8×8 과 같은 결론.
3. **bias 0 vs −4 는 방향만 일관.** bm4 가 seed 1개뿐이라 확정 아님.
4. **단일 config seed 반복 부재** (3-1 한계). seed 2/3/4 추가 예정.

## 6. 임의로 정한 것

1. **EPOCHS=32,000** — trainer 의 1 epoch 은 rows 가 아니라 **groups/batch** 다
   (앵커 2건으로 검증: nq8 4376×3000/768=17,094 ↔ 실측 17,093; nq10 36907×900/768=43,250 ↔ 실측 43,250).
   GC 는 1,445 groups 라 1.88 step/epoch 이므로 "총 step 60k 이상" 요건에서 32,000 epochs 를 택했다.
   지시문의 추정 6,600 epochs 는 rows 기준(9.1 step/ep) 계산이라 12,418 step 으로 미달이었다.
2. **EVALINT=1000** → eval 32회 (요건 30~40회).
3. **`train_gc8_v2.sh` 기본값을 GC 용으로 변경** (`BETA:-0.5`, `KL_RED:-sum`) + `EVALINT` 손잡이 추가.
   N-Queens 기본값(0.07/mean)이 yaml 을 조용히 덮어쓰는 침묵 실패를 막기 위함이며,
   launch 명령에도 명시해 이중 방어했다.
4. **정점 = raw conflict 최저 step** (accuracy 아님). 논문 GC 헤드라인이 conflict 이므로.
   차점도 함께 재서 요행이 아님을 확인했다.
