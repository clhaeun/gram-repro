# REPORT_pairexpand_50 — N-Queens 빌더 pair 확장 (2026-08-02)

## 1. 변경 내용 (dataset/build_nqueens_dataset.py)

실제 코드 변경은 두 곳뿐이다.

1. **test 절단 제거** (`convert_subset`): `if set_name == "test": sidxs = sidxs[:1]` 삭제.
   train 은 원래부터 전 해를 저장하고 있었고, test 만 입력당 1행으로 잘리고 있었다.
   이제 양쪽 split 모두 입력당 해 개수만큼 행을 저장한다. `sidxs = sorted(rows_by_key[h])`,
   `sols` 는 정렬된 해 목록 그대로 — 행 순서 결정론적, 셔플 없음.
2. **group = 행 단위** (`convert_subset`): `group_indices.append(puzzle_id)` 를 per-input
   루프 밖에서 per-row 루프 안으로 이동. 사수님 로그 "Saved train: 107494 groups,
   107494 puzzles" 기준. epoch = groups/batch 이므로 step 수 계산이 여기 걸린다.

판단 근거(GRAM posterior/prior 다해 신호, GC 빌더 선례)는 지시대로 코드 주석으로 남겼다.

### split 순서 확인 (★ 함정 항목)
현재 코드는 **이미 올바른 순서**다: `build_pairs()` 가 unique input 해시를 seed 0
permutation 으로 85:15 로 나눈 뒤(`build_nqueens_dataset.py:118-123`), `convert_subset` 이
각 split 안에서 확장한다. 순서 변경 불필요, leakage 구조적으로 0 (검증 [3]에서 실측 0 확인).
split seed 는 기존 0 유지.

## 4. 학습 영향 (착수 전 필독)

group 수가 바뀌었으므로 **같은 EPOCHS 값이 다른 step 수를 만든다**:

| | groups (구→신) | steps/epoch (batch 768) | 기존 step 예산 재현용 epochs |
|---|---|---|---|
| nq8 train | 4,376 → 7,194 | 5.70 → 9.37 | 68,340 steps ≈ 7,296ep (구 12,000ep) |
| nq10 train | 36,907 → 107,480 | 48.06 → 139.9 | 60,522 steps ≈ 432ep (구 1,260ep) |

`pretrain.py` 의 `assert epochs % eval_interval == 0` 주의 (nq10 EPOCHS=1250 사고 전례).
launch 는 지시 대기 — 이번 라운드는 빌드+검증까지.

- **기존 checkpoint 전부(v1~v7, nq8/nq10)는 `-uniq` 데이터 조건**(test 입력당 1행,
  group=unique input)으로 학습·평가된 것이다. 새 데이터 학습분과 직접 비교 시
  test 축이 다름(6,513 입력 1행 vs 19,220 행)을 반드시 병기할 것.
- harness/coverage 는 sidecar 기준이라 영향 없음 (sidecar 내용은 시드 동일 재빌드로 동일).

- 기존 v5h/v6h harness 32건은 "-uniq 조건" (test 입력당 1행, 6,513행 축) — 새 fin_* 결과와
